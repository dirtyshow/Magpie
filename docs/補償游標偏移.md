# 補償游標偏移

本文說明「武林立志傳」以 Magpie 全螢幕縮放時，游標無法移到畫面頂端的原因，以及「補償游標偏移」選項如何解決這個問題。

## 現象

| 情況 | 表現 |
| --- | --- |
| 不縮放，視窗化遊玩 | 正常，游標可以點到畫面每個角落 |
| Magpie 全螢幕縮放 | 遊戲游標移不到畫面最上面，頂端約 50px（縮放後）的區域點不到 |
| Lossless Scaling 縮放 | 遊戲游標在畫面頂端停住，但實際游標還能繼續往上移，彷彿畫面上方有一塊「看不到卻能移過去」的區域 |

其他遊戲搭配 Magpie 都正常，只有這款遊戲會發生。

## 原因

反組譯 `WLS.exe` 後發現，遊戲用下面的方式計算游標位置（位於 `0x4042bb` 附近）：

```c
POINT pt;
RECT wr;
GetCursorPos(&pt);                // 游標的螢幕座標
GetWindowRect(hwnd, &wr);         // 整個視窗的矩形，包含標題列和邊框
x = clamp(pt.x - wr.left, 0, 800);
y = clamp(pt.y - wr.top,  0, 600);
```

正確的做法應該以**客戶區**（遊戲畫面本身）的左上角為原點，例如使用 `ScreenToClient`。這款遊戲卻以**整個視窗**的左上角為原點，因此算出的遊戲內座標比實際位置多了一段偏移：

- Y 方向多出標題列加上邊框的高度（約 30px）
- X 方向多出左邊框的寬度（約數 px）

此外，遊戲呼叫 `ShowCursor(FALSE)` 隱藏系統游標，畫面上看到的是遊戲依自己算出的座標所畫的游標，所以玩家察覺不到這段偏移。

### 為什麼不縮放時正常

系統游標沒有被限制，可以移到標題列上。這時 `pt.y - wr.top` 能算到 0，遊戲游標就到得了畫面頂端，只是玩家看不出實際游標其實停在標題列上。

### 為什麼 Lossless Scaling 會有「看不到的區域」

Lossless Scaling 不限制游標，系統游標可以移進標題列，所以遊戲游標到得了頂端。但標題列不在縮放畫面裡，因此看起來像是畫面上方有一塊看不到、卻能移過去的區域。

### 為什麼 Magpie 點不到頂端

Magpie 縮放時會用 `ClipCursor` 把系統游標限制在客戶區內（`CursorManager::_ClipCursorForMonitors`）。系統游標最高只能到客戶區頂端，遊戲算出的 Y 最小值等於標題列高度。

標題列約 30px，乘上全螢幕縮放倍率（約 1.5～2 倍）後，正好是頂端約 50px 點不到的區域。

## 解決方式：「補償游標偏移」選項

開啟後，Magpie 換算與限制游標時，改用往左上平移「客戶區相對於視窗矩形的偏移量」後的源矩形：

- 系統游標可以進入標題列和邊框
- 遊戲算出的座標剛好對應整個畫面（0～800 × 0～600）
- 縮放畫面上點擊的位置，與遊戲認定的位置一致

### 使用方法

1. 在 Magpie 為武林立志傳建立設定檔
2. 在「游標」分組打開 **「補償游標偏移」**
3. 「擷取標題欄」保持關閉
4. 以全螢幕模式縮放

### 實作細節

| 檔案 | 修改 |
| --- | --- |
| `src/Magpie.Core/SrcTracker.h/.cpp` | 縮放開始時記錄 `ClientOffset()`，也就是客戶區左上角相對 `GetWindowRect` 左上角的偏移。視窗移動時兩者同步移動，尺寸改變則會重新縮放，所以只需計算一次 |
| `src/Magpie.Core/CursorManager.cpp` | 新增 `CursorSrcRect()`。開啟選項時回傳平移後的源矩形。`SrcToScaling`、`ScalingToSrc`、`_UpdateCursorState`、`_ClipCursorForMonitors`、`_StopCapture` 改用它取代 `Renderer::SrcRect()` |
| `src/Magpie.Core/ScalingWindow.cpp` | 全螢幕縮放開始時，若平移後矩形的左上角（即標題列）不在螢幕上，將源視窗移到螢幕中央，否則系統游標到不了那裡 |
| `src/Magpie.Core/include/ScalingOptions.h` | 新增 `ScalingFlags::CompensateCursorOffset` |
| `src/Magpie/*` | 設定檔鍵名 `compensateCursorOffset`、設定頁開關，以及 en-US、zh-Hans、zh-Hant 字串 |

### 注意事項

- **只對這類遊戲開啟。** 正常計算座標的遊戲開了這個選項，游標反而會錯位。
- 系統游標實際停在遊戲視窗的標題列上時，**按住左鍵拖曳**可能會讓 Windows 移動遊戲視窗，Magpie 隨後會重新開始縮放。不縮放直接遊玩時也有同樣的行為。
- 這款遊戲用 `GetAsyncKeyState(VK_LBUTTON)` 輪詢滑鼠按鍵，所以游標在標題列上時點擊仍然有效。若其他遊戲改用 `WM_LBUTTONDOWN` 等客戶區訊息讀取按鍵，在標題列範圍內的點擊將不會被遊戲收到。
- 若遊戲視窗可調整大小，游標移到邊框時，Magpie 可能把該處判定為調整大小的區域而暫時放開游標。

## 驗證

開啟「補償游標偏移」後以 Magpie 全螢幕縮放武林立志傳，游標已可到達畫面頂端，實測成功。
